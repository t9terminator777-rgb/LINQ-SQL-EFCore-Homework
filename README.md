# Учебный проект: LINQ, SQL и Entity Framework Core

Отдельный проект на C# и ASP.NET Core Web API для практики LINQ, SQL, ORM и EF Core. Старые учебные проекты в этот репозиторий не входят.

## Запуск в Visual Studio Code

1. Откройте эту папку в VS Code.
2. В меню **Terminal → New Terminal** выполните:

   ```powershell
   dotnet restore
   dotnet run
   ```

3. Откройте в браузере **http://localhost:5198/swagger**.
4. В Swagger выберите нужный раздел и нажмите **Try it out → Execute**. Начальные данные создаются автоматически при первом запуске.

Остановить сервер можно сочетанием **Ctrl+C** в терминале. Файл SQLite `clinic.db` создаётся рядом с проектом и сохраняет данные между запусками.

## Что реализовано

- **Пациенты** (`/api/Patients`): список, поиск по имени/email, карточка, создание, редактирование и удаление.
- **Справки** (`/api/Spravki`): CRUD, поиск и сортировка по цене, проверка существования пациента и вида справки.
- **Виды справок** (`/api/SpravkaTypes`): каталог с ценой, сроком действия и описанием. Цену при выписке сервер берёт из каталога.
- **Запись на приём** (`/api/Appointments`): отдельный модуль с CRUD, фильтром по пациенту/статусу и проверками.
- **LINQ-примеры** (`/api/Linq/examples`): фильтр, выбор полей, сортировка, группировка, подсчёт, проверка наличия и сумма.
- **Справки пациента** (`/api/Patients/{id}/spravki`) и отдельный запрос `/api/Linq/spravki-by-patient/{patientId}`.

Начальные записи нужны, чтобы сразу увидеть непустые ответы GET. Это учебные данные, а не настоящие медицинские сведения.

## Методы HTTP и ожидаемые ответы

| Метод | Пример адреса | Результат |
|---|---|---|
| GET | `/api/Patients` | список пациентов, код 200 |
| GET | `/api/Patients/1` | пациент или 404 |
| POST | `/api/Patients` | создание пациента, код 201 |
| PUT | `/api/Patients/1` | обновление пациента, код 200 |
| DELETE | `/api/Patients/1` | удаление, код 204; вместе с пациентом удаляются его справки и приёмы |

Такой же набор CRUD-операций есть у справок, видов справок и записей на приём. Для неверного тела запроса возвращается 400, для отсутствующего объекта — 404, при конфликте — 409.

### Пример POST пациента

```json
{
  "name": "Новый пациент",
  "birthDate": "2001-04-12T00:00:00Z",
  "phone": "+996700111222",
  "email": "new.patient@example.com",
  "bloodType": "B+"
}
```

### Пример POST справки

```json
{
  "patientId": 1,
  "spravkaTypeId": 3,
  "issuedAt": "2026-11-09T10:00:00Z",
  "notes": "Пример для Swagger"
}
```

В запросе указывается ID пациента и вида справки. Название и стоимость берутся из каталога, поэтому клиент не может случайно прислать свою цену.

## LINQ и SQL

LINQ — запросы к коллекциям и данным с помощью C#. В этом проекте запросы выполняются через EF Core и преобразуются в SQL для выбранной базы.

- `Where` оставляет строки по условию.
- `Select` выбирает нужные поля.
- `OrderBy` / `OrderByDescending` сортируют.
- `FirstOrDefaultAsync` ищет первый объект или возвращает `null`.
- `CountAsync`, `AnyAsync`, `SumAsync` считают количество, проверяют наличие и находят сумму.
- `GroupBy` группирует строки, `ToListAsync` выполняет запрос и получает список.

SQL-примеры `SELECT`, `WHERE`, `ORDER BY`, `JOIN`, `INSERT`, `UPDATE`, `DELETE` собраны в [SqlExamples.sql](SqlExamples.sql). `UPDATE` и `DELETE` всегда должны содержать условие `WHERE`, чтобы не изменить всю таблицу.

## EF Core, ORM и связи

- **ORM** сопоставляет классы C# с таблицами базы.
- `ClinicDbContext` — контекст работы с БД, а `DbSet<Patient>`, `DbSet<Spravka>` и другие наборы соответствуют таблицам.
- Связи: один пациент может иметь много справок и приёмов; каждая справка связана с одним видом справки.
- При первом запуске `EnsureCreatedAsync` создаёт таблицы, а `SeedData` добавляет демонстрационные записи.
- **Важно:** этот учебный пример использует `EnsureCreated`, а не миграции. Для самостоятельной практики с миграциями замените вызов `EnsureCreatedAsync` на `MigrateAsync`, добавьте пакет `Microsoft.EntityFrameworkCore.Design`, затем создайте миграцию командой `dotnet ef migrations add InitialCreate` и примените её командой `dotnet ef database update`. Не смешивайте `EnsureCreated` и миграции для одной базы.

## SQLite и PostgreSQL

По умолчанию выбран SQLite: это один локальный файл `clinic.db`, отдельный сервер устанавливать не нужно. В проект также добавлен EF Core провайдер PostgreSQL. Чтобы переключить приложение на уже запущенный PostgreSQL-сервер, в PowerShell задайте свою строку подключения (пароль не сохраняйте в Git) и перезапустите приложение:

```powershell
$env:Database__Provider = "postgres"
$env:ConnectionStrings__Postgres = "Host=localhost;Port=5432;Database=clinic;Username=postgres;Password=ВАШ_ПАРОЛЬ"
dotnet run
```

Если переменная окружения не задана, приложение использует SQLite. Режим SQLite проверяется как основной учебный сценарий; подключение к PostgreSQL требует установленного и запущенного PostgreSQL-сервера.
